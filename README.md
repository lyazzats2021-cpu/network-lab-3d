# NETWORK LAB 3D — Путешествие пакета данных

Первый этап браузерного 3D-тренажёра по компьютерным сетям для студентов колледжа 16–18 лет. В лаборатории можно осмотреть два настольных ПК и коммутатор, проследить Ethernet-кабели и узнать роль каждого устройства по его карточке.

Сцена построена из геометрии Three.js. Проект использует JavaScript, HTML, CSS и Vite. Для работы сайта достаточно статического хостинга и браузера с WebGL 2. Внешние API и учётные данные не нужны.

## Локальный запуск

Требуется Node.js 20.19+ в ветке 20.x или Node.js 22.12+. В GitHub Actions используется Node.js 24.

```bash
npm ci
npm run dev
```

Откройте адрес из вывода Vite. По умолчанию это `http://localhost:5173/`.

## Управление

| Действие | Мышь и клавиатура | Сенсорный экран |
| --- | --- | --- |
| Вращать камеру | Перетащите сцену левой кнопкой мыши или используйте стрелки, когда холст в фокусе | Перетащите сцену одним пальцем |
| Менять масштаб | Прокрутите колесо, нажмите кнопки «+» и «−» на сцене или клавиши «+» и «−», когда холст в фокусе | Сведите или разведите два пальца либо коснитесь кнопок «+» и «−» |
| Выбрать устройство | Щёлкните устройство, его метку или кнопку в списке. Кнопки доступны через Tab и Enter | Коснитесь устройства, его метки или кнопки в списке |
| Вернуть начальный ракурс | Нажмите «Сбросить камеру» или Home, когда холст в фокусе | Коснитесь кнопки со стрелкой по кругу |

Выбор устройства включает подсветку его корпуса или рамки и обновляет информационную карточку. ПК 01 соединён с портом 1 голубым кабелем, ПК 02 соединён с портом 2 жёлтым кабелем.

## Практический уровень «Собери локальную сеть»

Откройте «Собери локальную сеть» в верхнем меню. Выберите компьютер в сцене или в списке, нажмите его порт RJ‑45 и выберите свободный порт коммутатора. Номера портов видны на корпусе коммутатора и в панели. Все кнопки панели доступны через Tab и Enter и работают касанием.

Подключите каждый из четырёх ПК к отдельному порту и нажмите «Проверить сеть». Чтобы увидеть разбор ошибки, соедините два компьютера напрямую и снова проверьте сеть. Кнопка «Удалить» рядом с соединением освобождает оба порта. «Начать уровень заново» удаляет все кабели и возвращает начальный ракурс.

## Практический уровень «IP-МАСТЕР 3D»

1. Соберите сеть на первом уровне, затем в той же вкладке откройте **IP-МАСТЕР 3D**. При переходе между уровнями кабели и сохранённые настройки ПК остаются на месте.
2. Выберите каждый из четырёх ПК в сцене или в панели. Введите IPv4-адрес и маску по условию задачи и нажмите **Сохранить параметры**.
3. Нажмите **Проверить IP-адреса**, чтобы сверить данные с адресным планом. Если есть ошибки, исправьте и сохраните настройки, затем повторите проверку.
4. Выберите два ПК и нажмите **Проверить связь**. При успехе в сцене видно, как сигнал проходит туда и обратно по кабелям. Удалите кабель одного из этих ПК на первом уровне и повторите проверку, чтобы увидеть сообщение об отсутствии физического пути.

После развёртывания второй уровень открывается из меню GitHub Pages или добавлением `#ip` к адресу сайта. При прямом открытии в новой вкладке сначала соберите физическую сеть на первом уровне.

## Практический уровень «Путешествие пакета»

1. В одной вкладке соберите сеть на первом уровне и сохраните IPv4-настройки в **IP-МАСТЕР 3D**. Откройте **Путешествие пакета** из меню.
2. Выберите ПК 01 и ПК 03. Нажмите **Отправить пакет**. Жёлтый ромб обозначает ARP-сообщение, голубой куб — Ethernet-кадр с IP-пакетом. Журнал **Путь пакета** отмечает этапы передачи. Можно поставить показ на паузу или изменить скорость.
3. Нажмите **Повторить** после доставки. ARP-кэш используется повторно для той же пары. Измените кабели или сохранённые IP, чтобы увидеть, как проверка объясняет ошибку.
4. Под сценой выполните четыре задания. Первое проверяет завершённую отправку, остальные проверяют ответы и показывают объяснения.

Это упрощённая модель Ethernet, ARP и доставки IPv4 в одной локальной сети. Уровень открывается из меню сайта или по фрагменту `#packet`.

## Проверка и сборка

```bash
npm run check
npm run build
npm run preview
```

`check` проверяет синтаксис модулей и запускает тесты топологии, IPv4 и связи. `build` записывает готовый сайт в `dist/`. Последняя команда показывает локальный адрес для проверки собранного сайта.

## Публикация на GitHub Pages

1. Сохраните изменения в GitHub и объедините их с веткой `main`.
2. В репозитории откройте **Settings → Pages** и выберите **GitHub Actions** в поле **Source**.
3. Откройте вкладку **Actions** и запустите workflow **GitHub Pages** вручную или дождитесь запуска при следующем обновлении `main`. После успешного развёртывания адрес сайта появится в выводе задания `deploy`.

Workflow устанавливает зависимости по lock-файлу, проверяет исходники, собирает проект и публикует `dist/`. В Vite задано `base: './'`, чтобы ресурсы загружались и из подпапки `/network-lab-3d/`.
